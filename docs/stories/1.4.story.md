# Story 1.4: Simple State Setup (MVP)

## Status
Ready for Development

## Story
**As a** developer,  
**I want** basic state management setup for auth, API calls, and offline storage,  
**So that** the app can handle user sessions and work offline

## Acceptance Criteria
1. Zustand store for auth state (user, session)
2. TanStack Query setup for API calls
3. MMKV configured for secure local storage
4. Basic auth state persistence
5. Simple offline queue (store failed requests)
6. Supabase client initialized

### Error Handling Patterns
- API errors: Display toast or inline error
- Network offline: Queue mutations, show offline indicator
- Auth errors: Redirect to login
- Use try/catch with meaningful error messages

### State Architecture (Simple!)
```
/src/
├── store/
│   ├── auth.ts         # Zustand auth store
│   └── index.ts        # Store exports
├── lib/
│   ├── supabase.ts     # Client & helpers
│   ├── storage.ts      # MMKV utilities
│   └── query-client.ts # TanStack setup
└── providers/
    └── app-providers.tsx # All providers
```

### MVP State Approach
- NO complex persistence
- NO state migrations  
- NO advanced caching
- NO optimistic updates (yet)
- Focus on WORKING basics

### Example Auth Store
```typescript
interface AuthState {
  user: User | null;
  session: Session | null;
  login: (email: string, password: string) => Promise<void>;
  logout: () => Promise<void>;
}
```
